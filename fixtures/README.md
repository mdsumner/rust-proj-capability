# Fixtures

| file | what it is | written by |
|---|---|---|
| [FIXTURES.md](FIXTURES.md) | catalog: one row per fixture, linking to a page per fixture under [catalog/](catalog/) | generated by `report/make_docs.py` |
| `fixtures-src.json` | the fixture list: what goes in | hand-written |
| `crs.json` | the fixture list with PROJ's answers: what the harness reads | generated by `oracle/oracle.py` |

## The fixtures

There are 93 fixtures. Each is a (src, dst, point) triple. They come in five
groups:

- `seed`: the sidebyside `crs/` seed list.
- `pair`: CRS-to-CRS pairs. Besides the brief's pairs, this includes:
  - NAD27 to NAD83, ED50 to WGS84;
  - ITRF2014 to GDA2020 at epoch 2025.0;
  - WGS 84 to WGS 84 + EGM2008 height;
  - geographic 3D to geocentric;
  - LV95 to LV03;
  - Mars.
- `form`: one CRS in several input syntaxes, units (US feet, grads), and
  unknown, invalid and deprecated input.
- `method`: the awkward projection methods, all on WGS84 unless the method
  needs its own ellipsoid.
- `edge`: pole, seam, antipode, far from the central meridian, Mercator at
  the pole.

A `dst` of the form `@export:AUTH:CODE:FMT` is filled in by the oracle with
PROJ's own export of that CRS. The `compare_to` field names a fixture whose
result is the authority-code reference, so that a bare string can be
measured against the code.

| item | value |
|---|---|
| image | ghcr.io/hypertidy/gdal-r-python-extras:latest |
| PROJ | 9.9.0 (`projinfo`: "Rel. 9.9.0, September 15th, 2026"; `pyproj.proj_version_str` 9.9.0) |
| pyproj | 3.8.0, linked to the image's /usr/local/lib/libproj.so.25 |
| proj.db | EPSG v13.102 (2026-08-27), ESRI ArcGIS Pro 3.6 |
| grids | none. `PROJ_DATA=.proj-nogrids` holds only proj.db, proj.ini and the init files (world, other.extra, nad27, nad83, nad.lst, CH, GL27, ITRF*). The image's 819 MB of proj-data is not used. |
| network | off: container `--network none` and `PROJ_NETWORK=OFF`. The oracle refuses to run if `pyproj.network.is_network_enabled()`. |
| axis order | `always_xy=True`: the oracle is normalised for visualisation (east, north). EPSG:4326, which is lat/lon by authority, is therefore compared as lon/lat. |

When the best operation needs a grid, PROJ falls back to another one. The

## Schema

The schema version is `environment.schema_version` in `crs.json`, currently
1. The harness refuses any other value. Bump it in `oracle/oracle.py` when a
field below changes meaning.

### fixtures-src.json: `fixtures[]`

| field | type | meaning |
|---|---|---|
| `id` | string | unique id. The prefix repeats the group. |
| `group` | string | `seed`, `pair`, `form`, `method` or `edge` |
| `src`, `dst` | string | CRS definitions: authority code, PROJ string, WKT, PROJJSON, or `@export:AUTH:CODE:FMT`. FMT is one of PROJ, WKT1_GDAL, WKT1_ESRI, WKT2_2015, WKT2_2019, PROJJSON, optionally with a `-BOUND` suffix (bind to WGS84 first). |
| `form` | string | the syntax of the definition being tested: `authority`, `proj`, `wkt1-gdal`, `wkt1-esri`, `wkt2` or `projjson` |
| `point` | number[2..4] | test point in src units, in east/north order, with optional z and t (decimal year) |
| `point_lonlat` | number[2] | used instead of `point` for projected sources. The oracle projects it onto src from src's own geodetic CRS. |
| `layers` | string[] | the capability layers (I1-I7, E1-E8) the fixture is evidence for |
| `compare_to` | string, optional | id of the reference fixture |
| `note` | string, optional | why the fixture exists |

### crs.json: top level

| field | meaning |
|---|---|
| `environment.schema_version` | schema version (1) |
| `environment.generated` | UTC time of the oracle run |
| `environment.proj_version`, `projinfo_banner`, `pyproj_version` | versions |
| `environment.epsg_version`, `epsg_date`, `esri_version` | from the proj.db `metadata` table |
| `environment.proj_data`, `proj_data_files` | the PROJ_DATA directory and its full file list |
| `environment.grid_files_present` | grid-like files found on PROJ_DATA. Must be empty; the oracle exits otherwise. |
| `environment.network_enabled` | `pyproj.network.is_network_enabled()`. Must be false. |
| `environment.grid_configuration`, `axis_order` | the run's conventions, in words |
| `fixtures[]` | one object per fixture, described below |

### crs.json: `fixtures[]`

Every field from `fixtures-src.json` is carried over, with these changes:

| field | meaning |
|---|---|
| `src`, `dst` | **literal** definitions, with `@export:` references resolved. `dst` is null if the export failed. |
| `src_ref`, `dst_ref` | the definitions as written in `fixtures-src.json` |
| `point` | the resolved source point. `point_lonlat` is dropped. |
| `oracle` | what PROJ did, described below |

### crs.json: `fixtures[].oracle`

Coordinates are in each CRS's native units, in east/north order. Geographic
coordinates are in the CRS's angular unit (grads for EPSG:4807).

| field | type | meaning |
|---|---|---|
| `resolved` | bool | both CRSs were built (`pyproj.CRS.from_user_input`) |
| `executed` | bool | the forward result is finite |
| `error` | string | why PROJ refused. Prefixed by the stage: `src:`, `dst:`, `src export:`, `dst export:`, `create:` or `forward:`. |
| `src_name`, `dst_name` | string | CRS names |
| `src_kind`, `dst_kind` | string | `geographic`, `projected`, `geocentric`, `vertical` or `other`. A compound CRS is `compound-<kind of horizontal member>`. |
| `src_unit`, `dst_unit` | string | unit of the first axis of the horizontal member |
| `src_unit_factor`, `dst_unit_factor` | number | metres per unit (linear) or radians per unit (angular) |
| `point` | number[] | source point, as in the fixture |
| `fwd` | number[] | forward result, with the same dimension as `point`. A non-finite value is stored as a string (`"inf"`). |
| `inv` | number[] | inverse of `fwd` back to src: PROJ's round trip |
| `inv_error` | string | inverse failure, if any |
| `op` | object | the operation used for the forward result, from `proj_trans_get_last_used_operation` |
| `op.name` | string | operation description, for example "ED50 to WGS 84 (28) (with axis order normalized for visualization)" |
| `op.accuracy` | number | metres; -1 means unknown |
| `op.ballpark` | bool | the name contains "ballpark" |
| `op.proj` | string or null | the operation as a PROJ pipeline |
| `op.single_operation` | bool, optional | true when the transformer wraps one operation and PROJ keeps no last-used record. The transformer itself is reported. |
| `inv_op` | object | the same as `op`, for the inverse |
| `transformer` | string | `Transformer.description` before any coordinate was transformed |
| `candidates` | object[] | operations PROJ considered (`TransformerGroup`): up to six available ones then up to six unavailable ones. Each has `name`, `accuracy` (m, -1 unknown) and `available` (false means a grid is missing). |
| `best_available` | bool | false when the top-ranked operation needs a missing grid |
| `candidates_error` | string | `TransformerGroup` failed |
| `warnings` | string[] | pyproj warnings while creating the transformer |
| `src_export`, `dst_export` | object | PROJ strings for the horizontal member, as described below |
| `*_export.proj` | string | bare PROJ string (`proj_as_proj_string`, via `CRS.to_proj4()`) |
| `*_export.proj_bound` | string | PROJ string of `proj_crs_create_bound_crs_to_WGS84` (via `projinfo --boundcrs-to-wgs84`). Identical to `proj` when PROJ declines to bind. |
| `*_export.wkt1_gdal_bound` | string | WKT1 GDAL of the bound CRS |
| `*_export.proj_full`, `proj_full_bound` | string | compound CRSs only: the export of the whole compound |
| `*_export.proj_error`, `proj_bound_error` | string | export failures |

The bare strings come from pyproj, not projinfo, because `projinfo -o PROJ`
silently binds to WGS84: it emits `+towgs84` for EPSG:2056.

To regenerate: `./run-in-image.sh python3 -I oracle/oracle.py`, then
`python3 report/make_docs.py` for the pages.
